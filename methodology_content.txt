## Data Source

This dashboard uses conflict event data from the **Armed Conflict Location & Event Data Project (ACLED)**, a real-time disaggregated data collection, analysis and crisis-mapping project.

- **Coverage:** Myanmar, February 2021 – present
- **API endpoint:** `https://api.acleddata.com/acled/read`
- **Update cadence:** The pipeline can be re-run at any time; only new events (since the last fetch) are downloaded and appended — no duplication.

---

## Data Collection & Storage

The pipeline (`pipeline/pipeline.py`) fetches events via the ACLED REST API in paginated batches and stores them in a local CSV cache (`data/raw/acled_myanmar.csv`). On subsequent runs, only events with `event_date` after the latest locally-stored date are fetched, keeping the dataset current without full re-downloads.

All processed data is saved as **Parquet** files, which preserve column data types and compress efficiently — typically 60–80% smaller than equivalent CSV files.

## Event Type Classification (`key_event`)

The raw ACLED data includes detailed `event_type` and `sub_event_type` fields. These are recoded into **9 higher-level categories** for clarity and visualization:

| Category | Logic |
|---|---|
| **Ground-based attack** | `event_type` ∈ {Battles, Explosions/Remote violence} AND `sub_event_type` ≠ Air/drone strike |
| **Air attack** | `sub_event_type` = Air/drone strike AND the notes do NOT mention "drone" AND actor is State forces |
| **Drone attack** | `sub_event_type` = Air/drone strike AND (notes mention "drone" OR actor is not State forces) |
| **Violence against civilians** | `event_type` = Violence against civilians |
| **Protests** | `event_type` = Protests |
| **Arrests** | `sub_event_type` = Arrests |
| **Looting/property destruction** | `sub_event_type` = Looting/property destruction |
| **Displacement** | `sub_event_type` = Other AND event notes contain the word "displacement" |
| **Others** | All remaining events |

The drone/air split uses two signals: whether the word *drone* appears in the event notes, and whether the actor is categorised as State forces (Myanmar military). Non-state actors using airstrikes are very rare and are classified as Drone attacks by convention.

## Geographic Matching (Township P-codes)

All events are matched to Myanmar's official **township-level P-codes** (Tsp_Pcode, e.g. `MMR001001`) using the ACLED `admin3` field:

1. A reference table of admin3 names → P-codes is built from the GeoJSON boundary file.
2. The pipeline strips punctuation and normalises case before joining on admin3 name.
3. Events that cannot be matched (typically events recorded only at state/region level) are assigned a null P-code and excluded from map visualizations, but are still counted in KPI totals.

---

## Actor-Level Data

For combat analysis (Actor Analysis page), a separate **actor-level table** is constructed from events categorised as Ground-based attack, Air attack, or Drone attack. Each event can have multiple actors (primary attacker, primary defender, associated forces). The pipeline:

1. **Unpivots** actors: each event generates one or more rows — one per actor-role pair.
2. **Role assignment:** An actor is labelled `offend` (attacker) or `being_offended` (defender) based on their side in the event.
3. **Alliance pairs:** For each event, all actors on the same side are cross-joined to create an alliance pair table — used to populate the Alliance Network table.
4. **Civilian exclusion:** Generic civilian entries (e.g., *Civilians (Myanmar)*) are excluded from the actor dropdown and bar chart. Named civilian-affiliated defence forces (e.g., *Mountain Knights Civilian Defense Force*) are retained as they are distinct military actors.

## Pre-aggregated Monthly Data

To ensure fast page rendering without expensive in-browser computation, the pipeline pre-aggregates events into a **monthly township summary table** (`monthly_township.parquet`):

- Dimensions: `Tsp_Pcode`, `admin1` (State/Region), `month` (YYYY-MM), `key_event`
- Metrics: `events` (count), `fatalities` (sum)
- Size: ~28,000 rows — roughly 100 KB in memory

Dashboard callbacks filter this table (instead of the full 90,000-row event log) to generate choropleth matrices and trend charts. This reduces per-callback data processing by ~95%.

---

## Map Rendering Performance

Myanmar's 330 townships are rendered as a choropleth using the official boundary GeoJSON (~12 MB). To keep the animated map responsive:

- **First load:** The full GeoJSON is embedded once in the figure.
- **Subsequent slider ticks:** Only the 330 fill-colour values (`z`) are sent to the browser via Plotly's `Patch()` mechanism (~1 KB per tick, vs 12 MB for a full figure rebuild).
- **Quarterly aggregation:** The animated map groups events by quarter (Q1–Q4) rather than month. This yields ~20 frames instead of 60, making temporal patterns more visible and animation smoother.

## Known Limitations

- **Reporting bias:** Conflict events in remote or restricted areas (e.g., parts of Shan, Chin, and Sagaing states) may be under-reported due to limited journalist and monitor access.
- **Fatality counts:** ACLED records the *best estimate* of fatalities at time of reporting. These may be revised as more information becomes available.
- **Actor names:** ACLED uses standardised actor names that may differ from local terminology or self-identification.
- **Civilian defence forces:** The line between civilian-based resistance forces and armed groups is context-dependent. This dashboard follows ACLED's classifications.
- **Drone detection:** The heuristic for distinguishing drone attacks (notes contain "drone") may miss some cases where drone use is not mentioned in the event description.
